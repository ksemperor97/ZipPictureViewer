# Zip Picture Viewer 완성도 개선 실행 계획

- 문서 상태: 구현 준비 완료
- 기준 코드: `2d16858` (`main`, 2026-05-01)
- 감사 기준일: 2026-07-13
- 목표 릴리스: 안정화 릴리스 `v1.1.0`

## 1. 목적

Zip Picture Viewer의 핵심 가치는 여러 폴더와 ZIP/CBZ 안의 이미지를 끊김 없이 하나의 목록처럼 보는 것이다. 현재 구현은 정상 파일을 대상으로 한 기본 흐름은 동작하지만, 손상 파일, 경로 변화, 대용량 자료, 구형 ZIP 인코딩, 작은 창, 구형 macOS 같은 실제 환경에서 상태 불일치나 실행 실패가 발생한다.

이 계획의 목표는 다음과 같다.

1. 파일 하나의 오류가 전체 감상 흐름을 중단하지 않게 한다.
2. 화면, 현재 위치, 열린 루트, 세션 데이터가 항상 같은 상태를 가리키게 한다.
3. 큰 컬렉션에서도 UI가 응답성을 유지하고 메모리 사용량에 상한이 있게 한다.
4. 폴더 이동, 세션 복원, 한글 ZIP 이름을 예측 가능하게 처리한다.
5. macOS와 Windows 배포본이 명시한 환경에서 실제로 실행된다는 증거를 남긴다.
6. 이후 기능 추가가 가능하도록 UI와 도메인 로직의 책임을 분리한다.

## 2. 제품 범위와 지원 계약

완성도 판단 기준이 흔들리지 않도록 `v1.1.0`의 지원 범위를 먼저 고정한다.

### 2.1 지원 환경

- macOS 13 이상, Apple Silicon
- Windows 10 22H2 이상 및 Windows 11, x64
- Linux는 소스 실행만 best-effort로 지원한다. 패키지 배포를 시작하려면 별도 CI와 수동 검증 환경을 추가한다.

### 2.2 지원 컨테이너와 이미지

- 컨테이너: `.zip`, `.cbz`, 일반 이미지 폴더
- 이미지: `.bmp`, `.gif`, `.jpeg`, `.jpg`, `.png`, `.webp`
- ZIP 이름 인코딩: 표준 UTF-8/CP437 및 레거시 CP949
- 암호화 ZIP: 표준 ZipCrypto는 세션 한정 암호 입력을 지원하고, AES ZIP은 명시적인 미지원 오류를 표시한다. AES 지원을 위해 새 런타임 의존성을 추가하는 일은 별도 결정으로 남긴다.
- `.rar`, `.7z`, HEIC/AVIF/TIFF는 이번 릴리스 범위 밖이며 README에 명시한다.

### 2.3 핵심 사용자 흐름

- 폴더 또는 단일 ZIP/CBZ를 열기와 드래그 앤 드롭으로 연다.
- 이미지 단위와 묶음 단위로 앞뒤 이동한다.
- 선택한 루트의 형제 폴더로 이동한다.
- GIF를 재생한다.
- 화면 맞춤, 100% 보기, 확대/축소와 이동을 제공한다.
- 최근 폴더와 정확한 이미지 위치를 복원한다.
- 읽지 못한 파일은 감상 흐름을 막지 않고 오류 목록에서 확인할 수 있다.
- 변경된 폴더와 아카이브를 명시적으로 새로고침할 수 있다.

## 3. 우선순위 정의

- P0: 실행 불가, 데이터/상태 혼합, 전체 흐름 중단. 릴리스 전에 반드시 수정한다.
- P1: 명세와 다른 이동·복원, 잘못된 화면, 큰 자료에서의 정지 또는 메모리 고갈. 릴리스 전에 수정한다.
- P2: 희귀 형식, 사용성 저하, 배포 재현성 문제. 원칙적으로 릴리스 전에 수정하되 명확한 제한 문서가 있으면 후속 릴리스로 분리할 수 있다.

## 5. 반드시 지켜야 할 상태 불변식

구현 중 아래 규칙을 코드와 테스트에 직접 반영한다.

1. `current_root`, `entries`, `current_index`, 화면 이미지, 파일명, 위치 표시는 하나의 로드 세대(generation)에 속해야 한다.
2. 새 폴더 스캔이 성공하기 전에는 기존 뷰어 상태를 부분적으로 덮어쓰지 않는다.
3. 이미지 디코드에 실패해도 현재 항목의 파일명과 위치는 갱신되고 이전 이미지 픽스맵은 제거된다.
4. 한 컨테이너의 실패는 다른 컨테이너의 인덱싱과 감상을 막지 않는다.
5. 사용자에게 보이지 않게 이미지나 아카이브를 누락하지 않는다.
6. 선택한 논리 경로와 파일 접근용 실제 경로를 구분한다.
7. 비동기 작업의 오래된 결과는 최신 상태에 반영되지 않는다.
8. 캐시는 파일 개수가 아니라 바이트 예산 안에서 동작한다.
9. 세션 파일은 원자적으로 교체하며, 부분 쓰기로 기존 세션을 잃지 않는다.

## 6. 제안 모듈 구조

현재 작은 도메인 모듈은 유지하고, 568줄인 `ui.py`의 책임을 단계적으로 분리한다. 한 번에 패키지 구조로 바꾸지 않고 호환 진입점을 남긴다.

```text
zippictureviewer/
├── __main__.py               # CLI 인수와 앱 진입점
├── ui.py                     # run_app 및 기존 import 호환 re-export
├── viewer_window.py          # MainWindow 조립과 Qt signal 연결
├── viewer_controller.py      # 폴더 로드, 이동, 오류 처리 상태 전이
├── viewer_widgets.py         # FloatingPanel, ViewerSurface 등 단순 위젯
├── image_view.py             # 정지 이미지/GIF 렌더링, fit/zoom/pan
├── scan_worker.py            # 취소 가능한 비동기 스캔
├── folder_context.py         # 논리 루트, 실제 루트, 형제 이동 규칙
├── archive_scanner.py        # ScanResult 생성, 컨테이너별 오류 격리
├── image_loader.py           # QImage/QMovie 검증과 리소스 제한
├── image_cache.py            # 바이트 예산 LRU와 파일 revision
├── viewer_state.py           # 순수 탐색 상태
├── session_store.py          # 스키마 마이그레이션과 원자적 저장
├── models.py                 # ImageEntry, ScanIssue, LoadResult 등
└── natural_sort.py
```

### 6.1 핵심 모델

- `FolderContext`
  - `logical_path`: 사용자가 선택한 경로. 세션과 형제 이동에 사용한다.
  - `access_path`: 실제 파일 접근에 사용할 정규화 경로.
  - `source_kind`: 폴더 또는 단일 아카이브.
- `ContainerRevision`
  - 경로, `mtime_ns`, 파일 크기. 캐시 무효화에 사용한다.
- `ArchiveMemberId`
  - 파일명뿐 아니라 ZIP 레코드 인덱스 또는 `header_offset`, CRC를 포함한다.
- `ScanIssue`
  - 대상 경로, 단계, 오류 종류, 사용자 메시지, 재시도 가능 여부를 보관한다.
- `ScanResult`
  - `entries`, `issues`, 취소 여부, generation을 함께 반환한다.
- `DisplayResult`
  - 정지 이미지, 애니메이션, 표시 가능한 오류 상태 중 하나만 갖는다.

## 7. 구현 마일스톤

### M0. 지원 계약과 회귀 테스트 기반

목표는 수정 전에 현재 결함을 자동으로 재현할 수 있게 만드는 것이다.

작업:

1. `[dev]` 의존성에 `pytest`, `pytest-qt`를 추가한다. `pytest-qt`는 Qt 이벤트 루프, shortcut, signal 검증을 안정적으로 수행하기 위한 개발 전용 의존성으로 제한한다.
2. 테스트 파일을 책임별로 분리한다.

```text
tests/
├── helpers.py
├── test_archive_scanner.py
├── test_image_loader.py
├── test_image_cache.py
├── test_viewer_state.py
├── test_folder_navigation.py
├── test_session_store.py
├── test_viewer_controller.py
└── test_main_window.py
```

3. 테스트 안에서 다음 자료를 임시 생성한다.
   - 자연 정렬되는 일반 이미지와 ZIP/CBZ
   - 손상 정지 이미지와 6바이트 `GIF89a`
   - `chmod 000` ZIP과 스캔 중 삭제되는 ZIP
   - CP949 파일명을 가진 ZIP
   - 같은 이름의 멤버가 두 번 있는 ZIP
   - 압축률이 높은 멤버와 큰 픽셀 크기 이미지
   - 심볼릭 링크 루트와 여러 계층의 형제 폴더
4. README에 실제 지원 OS·형식과 알려진 제한을 우선 명시한다.

완료 조건:

- 각 F-ID에 대응하는 회귀 테스트 이름이 존재한다.
- 수정과 테스트를 같은 커밋에 포함해 기본 브랜치에는 실패 테스트를 남기지 않는다.
- 순수 도메인 모듈의 핵심 분기 커버리지는 80% 이상이고, UI는 주요 사용자 흐름을 테스트한다.

### M1. 오류 격리와 화면 상태 일관성

목표는 손상 파일 하나로 뷰어가 멈추거나 거짓 화면을 표시하지 않게 하는 것이다.

작업:

1. 폴더 로드를 트랜잭션으로 바꾼다.
   - 스캔 시작 시 기존 상태를 유지한다.
   - 완성된 `ScanResult`를 받은 뒤 한 번에 `current_root`와 `entries`를 교체한다.
   - 전체 작업이 실패하거나 취소되면 기존 상태를 유지하고 비차단 오류를 표시한다.
2. 아카이브마다 `BadZipFile`, `OSError`, `RuntimeError`, 지원하지 않는 압축 방식을 격리해 `ScanIssue`로 수집한다.
3. 정지 이미지 디코드 실패 시 이전 픽스맵을 제거하고 오류 placeholder를 표시한다.
4. 오류 항목에서도 위치, 파일명, 이전/다음 버튼을 정상 갱신한다.
5. 반복되는 modal 경고창 대신 접을 수 있는 오류 요약 패널과 “다시 시도” 동작을 제공한다.
6. GIF는 첫 프레임 디코드 성공까지 확인한 뒤 표시 성공으로 처리한다. 재생 도중 오류도 상태에 반영한다.
7. 폴더에 읽을 수 있는 항목이 하나도 없더라도 “빈 폴더”, “지원 형식 없음”, “모든 컨테이너 실패”를 구분한다.

완료 조건:

- 첫 이미지와 중간 이미지가 손상된 경우 모두 버튼과 키보드로 계속 이동할 수 있다.
- 새 폴더 로드 실패 뒤 루트·목록·화면·세션이 이전 세대 또는 새 세대 중 하나로만 일치한다.
- 정상 ZIP과 실패 ZIP을 섞었을 때 정상 이미지는 모두 보이고 실패 목록도 확인할 수 있다.
- 손상 GIF가 정상 위치 표시와 함께 빈 화면으로 남지 않는다.

### M2. 폴더 이동과 세션 스키마 정비

목표는 사용자가 선택한 위치를 기준으로 이동하고 정확한 항목을 복원하는 것이다.

작업:

1. `FolderContext`를 도입해 논리 경로와 실제 접근 경로를 분리한다.
2. “이전/다음 폴더”는 언제나 `logical_path`의 형제를 기준으로 한다.
3. 현재 이미지 컨테이너의 형제 이동이 필요하다면 기존 명령에 섞지 않고 별도 동작으로 정의한다.
4. 세션 스키마를 버전 2로 올린다.

```json
{
  "version": 2,
  "last_root": {
    "logical_path": "...",
    "access_path": "...",
    "source_kind": "folder"
  },
  "positions": {
    "<logical-root>": {
      "container_id": "...",
      "member_id": "...",
      "container_index": 3,
      "global_index": 42
    }
  }
}
```

5. 버전 1 세션을 읽고 버전 2로 마이그레이션한다.
6. 폴더가 비어 있어도 성공적으로 열렸다면 마지막 루트로 저장한다.
7. 저장 항목이 사라졌을 때 다음 순서로 복원한다.
   - 정확한 멤버 ID
   - 같은 컨테이너의 가장 가까운 인덱스
   - 같은 컨테이너의 첫 항목
   - 전체 목록의 첫 항목
8. 임시 파일에 쓴 뒤 `os.replace()`로 세션 파일을 원자적으로 교체한다.

완료 조건:

- 직접 이미지, 루트 ZIP, 중첩 ZIP, 중첩 이미지 폴더 어디를 보고 있어도 형제 폴더 결과가 같다.
- 심볼릭 링크로 연 루트는 재실행 뒤에도 링크 문맥을 유지한다.
- 빈 폴더가 마지막 루트로 복원된다.
- 삭제된 항목 복원이 관계없는 다른 컨테이너로 과거 전역 인덱스를 그대로 적용하지 않는다.
- 손상 세션, 버전 1 세션, 동시 프로세스의 마지막 쓰기에 대해 안전하게 실패한다.

### M3. 아카이브 호환성, 식별자와 리소스 안전성

목표는 실제 ZIP 변형을 정확히 읽고 악성 또는 비정상 입력에 자원 상한을 적용하는 것이다.

작업:

1. `ImageEntry`가 ZIP 파일명 문자열 대신 정확한 `ZipInfo` 레코드를 재식별할 정보를 갖게 한다.
2. 중복 멤버는 레코드 인덱스 또는 `header_offset`으로 각각 읽는다.
3. ZIP revision을 `mtime_ns`와 파일 크기로 계산해 아카이브 교체 시 인덱스와 캐시를 무효화한다.
4. “새로고침”은 스캔 generation을 올리고 현재 항목을 ID로 다시 찾는다.
5. ZIP 이름 인코딩 정책을 추가한다.
   - UTF-8 flag는 항상 우선한다.
   - flag가 없는 이름은 자동/CP949/CP437 선택을 제공한다.
   - 자동 감지는 한글 환경의 명백한 mojibake를 보정하되, 사용자가 아카이브별로 덮어쓸 수 있게 한다.
6. 암호화 상태를 스캔 단계에서 감지한다.
   - ZipCrypto 암호는 메모리에만 보관한다.
   - 취소하거나 실패해도 다른 아카이브 감상을 계속한다.
   - AES 등 미지원 방식은 원인을 명확히 표시한다.
7. 초기 안전 한도를 도입하고 실제 자료 corpus로 조정한다.
   - 단일 멤버 비압축 크기: 기본 256 MiB
   - 이미지 픽셀 수: 기본 100 MP
   - 비압축 크기가 64 MiB 이상이면서 압축률 500배를 넘으면 사용자 확인 또는 차단
   - 정지 이미지 캐시: 기본 256 MiB
   - GIF `CacheAll`은 예산 안의 작은 파일에만 사용하고 나머지는 제한된 모드로 재생
8. 한도 초과는 일반 디코드 오류와 구분해 파일 크기와 조정 방법을 표시한다.

완료 조건:

- CP949 `가.jpg`가 올바르게 표시되고 자연 정렬된다.
- 같은 이름의 ZIP 멤버 두 개를 서로 다른 이미지로 볼 수 있다.
- ZIP 교체 후 새로고침하면 과거 픽스맵이 남지 않는다.
- 압축 폭탄과 초대형 이미지는 설정한 예산을 넘기기 전에 중단된다.
- 암호화 또는 지원하지 않는 압축 방식이 전체 스캔을 막지 않는다.

### M4. 비동기 처리와 뷰어 UI 완성

목표는 큰 컬렉션에서도 UI가 반응하고 기본 이미지 뷰어 동작을 제공하는 것이다.

작업:

1. 재귀 스캔을 한 번의 디렉터리 순회로 통합하고 worker에서 실행한다.
2. 스캔 진행률, 현재 경로, 취소 버튼을 제공한다.
3. 새 로드가 시작되면 이전 worker를 취소하고 generation이 다른 결과를 폐기한다.
4. 정지 이미지는 worker에서 `QImage`로 디코드하고 GUI 스레드에서만 `QPixmap`으로 변환한다.
5. 화면 맞춤에서는 viewport 크기에 맞춰 축소 디코드하고, 확대가 필요할 때만 더 높은 해상도를 요청한다.
6. 사전 로딩은 우선순위 큐로 현재±인접 항목만 처리하며 이동 방향을 반영한다.
7. 컨트롤을 반응형으로 바꾼다.
   - 충분한 폭: 현재의 전체 버튼
   - 좁은 폭: 핵심 탐색 버튼 + overflow 메뉴 또는 두 줄 배치
   - 버튼 텍스트가 최소 판독 폭 이하로 줄어들지 않게 한다.
8. 이미지 화면에 다음 기능을 추가한다.
   - fit, 100%, 확대/축소
   - 확대 상태의 드래그 이동
   - 더블클릭 또는 단축키로 fit/100% 전환
9. 폴더뿐 아니라 단일 ZIP/CBZ도 열기와 드롭으로 받을 수 있게 한다.
10. 새로고침, 오류 목록, 단축키 도움말을 overflow 메뉴에 배치한다.
11. 전체화면 진입 즉시 resize grip과 불필요한 컨트롤 가시성을 다시 계산한다.
12. 긴 경로는 말줄임 처리하되 tooltip과 선택 가능한 전체 텍스트를 제공한다.

성능 목표:

- 스캔 중 이벤트 루프의 단일 정지 구간은 일반적으로 100 ms를 넘지 않는다.
- 취소 요청은 500 ms 안에 UI 상태에 반영한다. 이미 시작된 단일 ZIP read는 안전 지점에서 종료할 수 있음을 문서화한다.
- 캐시가 설정한 바이트 예산을 지속적으로 초과하지 않는다.
- 1,000개 아카이브와 10,000개 이미지의 합성 corpus에서 스캔·탐색 benchmark를 CI 또는 정기 성능 작업으로 기록한다.

완료 조건:

- 스캔 중 창 이동, 취소, 닫기가 가능하다.
- 빠르게 여러 폴더를 선택해도 마지막 요청의 결과만 표시된다.
- 480px 폭에서도 핵심 조작이 판독 가능하고 접근 가능하다.
- fit/100%/zoom/pan 전환에서 이미지가 사라지거나 GIF가 중복 재생되지 않는다.
- 단일 ZIP 열기, 폴더 열기, 드롭이 같은 controller 경로를 사용한다.

### M5. 재현 가능한 macOS·Windows 배포

목표는 태그와 바이너리의 출처가 일치하고 지원 OS에서 실제 실행되는 릴리스를 만드는 것이다.

작업:

1. 버전의 단일 원천을 정한다. `pyproject.toml`에서 읽어 spec, 파일명, workflow가 사용하게 한다.
2. 릴리스 workflow는 입력된 태그를 명시적으로 checkout하고 태그 버전과 프로젝트 버전이 다르면 실패한다.
3. 패키징 의존성은 플랫폼별 constraints 파일로 고정한다.
4. macOS는 최소 OS 13을 보장하는 Python과 빌드 호스트를 사용한다.
   - python.org 호환 런타임 또는 최소 OS가 통제된 빌드 runner를 사용한다.
   - 모든 Mach-O의 `LC_BUILD_VERSION`을 자동 검사한다.
5. 사용하지 않는 Qt framework를 제거한 뒤 대응하는 Resources/Frameworks 심볼릭 링크도 함께 제거한다. 가능하면 PyInstaller 분석 단계에서 제외해 사후 삭제를 줄인다.
6. 개발용 ad-hoc 번들과 릴리스용 Developer ID 서명·notarization 번들을 구분한다.
7. Windows와 macOS 앱에 `--smoke-test` 모드를 추가한다.
   - GUI 초기화
   - 필수 이미지 플러그인 확인
   - 임시 폴더/ZIP의 한 장 디코드
   - 세션 임시 경로 쓰기
   - 성공 시 0으로 종료
8. 빌드 산출물에 commit SHA와 dependency manifest를 포함한다.
9. 릴리스 업로드 전에 SHA-256을 생성하고 release note에 기록한다.

macOS 게이트:

```bash
scripts/build_macos_app.sh
find -L dist/ZipPictureViewer.app -type l -print
codesign --verify --deep --strict --verbose=2 dist/ZipPictureViewer.app
```

- 첫 번째 `find`는 아무것도 출력하지 않아야 한다.
- 별도 검사 스크립트는 번들의 모든 Mach-O가 `minos <= 13.0`인지 검증해야 한다.
- 서명된 릴리스는 `spctl`과 notarization 검증도 통과해야 한다.

Windows 게이트:

```powershell

```

- Windows 10과 11 runner에서 각각 smoke test를 수행한다.
- `qwindows`, `qgif`, `qjpeg`, `qwebp` 플러그인 존재 여부를 확인한다.
- workflow artifact와 release asset이 동일한 SHA-256인지 확인한다.

완료 조건:

- macOS 13, 14, 15, 26의 실제 또는 신뢰할 수 있는 CI 환경에서 실행 증거가 있다.
- Windows 10과 11에서 실행·이미지 로드 smoke test가 통과한다.
- 깨진 심볼릭 링크가 없고 엄격한 코드서명 검증이 통과한다.
- 태그, 앱 버전, 파일명, 내장 commit SHA가 일치한다.

## 11. 주요 위험과 사전 결정이 필요한 항목

### CP949 자동 감지

flag가 없는 ZIP 이름은 CP437이 표준이므로 자동 CP949 변환은 오판 가능성이 있다. 자동 감지는 보조 기능으로 두고 아카이브별 수동 선택을 반드시 제공한다.

### 비동기 취소

표준 `zipfile`의 단일 read를 즉시 중단하기 어렵다. 멤버를 chunk 단위로 읽고 안전 지점에서 취소를 확인하거나, 작업 결과를 generation으로 폐기해야 한다. UI에 “취소 요청됨” 상태를 구분해 표시한다.

### 대형 이미지와 확대

fit 전용 축소 디코드는 메모리에 유리하지만 100% 확대에는 원본 데이터가 필요하다. 작은 이미지는 전체 디코드하고 큰 이미지는 요청 해상도 또는 tile 기반 접근을 사용하는 2단계 정책을 적용한다.

### macOS 서명과 notarization

Developer ID와 notarization 자격 증명은 코드만으로 해결할 수 없는 외부 조건이다. 자격 증명이 준비되지 않으면 개발용 ad-hoc 빌드와 정식 릴리스를 명확히 구분하고, 정식 릴리스 완료로 표시하지 않는다.

### 새 런타임 의존성

AES ZIP이나 고급 이미지 포맷을 위해 의존성이 필요하면 바이너리 크기, 라이선스, macOS/Windows 패키징 영향을 먼저 문서화하고 별도 PR로 결정한다. `v1.1.0`의 핵심 안정화 작업과 섞지 않는다.
